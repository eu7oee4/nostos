# nostos 设计页：首次引导 × 拼装单 × 会话段重铸

> 状态：2026-09-07 对齐稿（对话 + PLAN_companion §4.2/§4.3/§5/§6.3）；时区不进 profile 已拍板  
> 范围：一次 LLM 调用注入什么、何时重铸、首次进网页怎么开场  
> 非施工手册；拍板项可直接开工，未决项标出

---

## 0. 一句话

**稳定前缀吃缓存；易变后缀扛本轮；重铸只在会话段边界（软/硬闸），不是每轮重写历史。**  
主动 wake 的时刻由模型用 tool 定；APScheduler 只负责到点执行。

---

## 1. 和 PLAN 的对齐（重铸到底是什么）

PLAN §4.3 已拍板，**纠正「按节点每轮重铸对话」的误解**：

| 说法 | 对不对 |
|------|--------|
| 最近 N 条 / 最近 M 分钟滑动窗口 | ❌ 每轮前缀字节变 → 缓存全灭 |
| 会话段（episode）内纯追加 | ✅ 前缀不动，只付增量 |
| **重铸** = 关段时把本段提炼进记忆，下段用「前缀骨架 + 新召回 + 新对话」开场 | ✅ |
| 软闸：tokens 过线 **且** 缓存已死（如闲置超 TTL）→ 机会主义重建，零额外成本 | ✅ |
| 硬闸：tokens 硬顶 → 轮末立刻重建，认赔一次全价 | ✅ |
| 每轮把历史改写成新「节点文案」 | ❌ 等于每轮硬闸，打穿缓存 |

**结论：** 拼装单里的「对话窗口」= **当前会话段的原始消息 append-only**，不是每轮重铸产物。重铸是段生命周期事件。

## 2. 一次调模型：固定拼装单（顺序 = 缓存纪律）

服从 PLAN：**稳定在前、易变在后；断点放在稳定性边界。**  
`tools` **不在** messages 序号里，是同一次请求的平行字段（schema 保持稳定）。

### 2.1 messages 前缀（尽量不变）

| # | 块 | 内容 | 变频 | 缓存 |
|---|----|------|------|------|
| 1 | **系统提示** | 通用规矩：怎么回 `user_name`、可主动找人、禁区（不提工具/调度）、安全红线（拒未成年人色情等）。**无前端修改入口** | 极低（发版才改） | 断点①大头 |
| 2 | **user_profile** | `nickname`（=拼装用的 user_name）、性别气质（她/他/祂）、伙伴称谓等稳定身份；**不含时区** | 低 | 随① |
| 3 | **persona** | 伙伴是谁、语气、关系；**与系统提示必须分开**；前端可改（MVP 单文件；git 版本回退后做） | 中（纠偏/用户改） | 断点②：改 persona 只炸②以后 |
| 4 | **对话窗口** | **本会话段** user/assistant 原文纯追加；每条带**服务端冻结时间戳**（见 §3） | 只追加 | 断点③在最新轮前 |

### 2.2 messages 后缀（每轮可变，不炸前缀缓存）

| # | 块 | 内容 |
|---|----|------|
| 5 | **召回记忆** | 「现在浮现在你脑海里的记忆有：…」md 摘要，有字符上限；空则整块省略（发言权：没注入不许评论） |
| 6 | **本轮时间锚** | 见 §3：服务端按配置时区格式化「此刻」放在后缀；另有消息冻结戳。**不进 profile / 系统前缀** |
| 7 | **本轮触发** | **二选一**：见 §2.3 |

### 2.3 本轮触发（7a / 7b）

- **7a 用户消息：** `user_name发来一条消息：…`（可含卡片选项结果 / 上传文件正文）
- **7b wake 开火：** `你醒了，user_name没找你` + wake 的 `note`/`intent`；允许「说或不说」。沉默时仍 `mark fired` + 留痕，前端不假装没响。

**wake 路径建议：** 仍走同一装配管线；`tools` 可收窄（例如只留 memory，或全留但靠 system 约束「主动来找时少乱改钟」）。**不另写第二条装配**（StarHub：复制装配管线 = 屎山源）。

### 2.4 tools（平行、稳定）

当前产品本体（不是「助手插件」）：

- `memory_list` / `memory_read` / `memory_write`
- `wake_set` / `wake_list` / `wake_cancel`（文案写清：`delay_seconds` 相对 / `wake_at` 绝对 ISO；**覆盖 = cancel 旧 + set 新，或 set 同逻辑 id 替换**）

说明文字尽量少改；改 tools schema = 部分厂商缓存一并失效。

### 2.5 刻意后置 / 暂不做

- pending wakes 列表注入：后加（利于模型决定覆盖）
- 护栏 prefs（安静时段/日上限）摘要：后加；**不是**「下一次几点」的决策者
- preferences 纠偏层（PLAN 块2）：MVP 可先并进 persona 直写；独立层在「说一句就变了」做强时再拆，以便只炸断点②

## 3. 时间感知（和 PLAN §6.3 对齐）

PLAN 拍板：**活时间不进 system**（每轮炸满前缀缓存）。

| 机制 | 做法 |
|------|------|
| 历史时间 | 每条消息（含伙伴回复）**服务端落库盖戳**；首次进入上下文即冻结，之后不改格式、不剥戳 |
| 「现在几点」 | **默认** = 本段最新一条消息上的戳（用户刚发的那条 = 近似现在） |
| 显式现在 | 每轮后缀 #6 带「此刻（服务端时区），日期+星期+钟点」；**禁止进系统前缀 / profile** |
| 时区 | **不写入 profile**。服务端配置（默认 `Asia/Shanghai`，可用环境变量）只用来格式化**每轮后缀时间锚**与消息戳展示；模型看末端即可 |
| 禁令 | 段中途改时间戳渲染格式；把 `time_now` 塞进系统前缀 |

模型用 tool 设 wake 时：相对延迟优先；绝对时间以后缀锚或最新消息戳为参考。

## 4. 会话段与重铸（施工要点）

```
开段 → 段内多轮纯追加（吃缓存）→ 关段条件触发
         → 提炼本段进 memories/（可夜间/大模型）
         → 下一段：系统+profile+persona +（空或新）对话 + 新召回…
```

**关段 / 重铸触发（合二为一）：**

1. **闲置超 TTL**（DeepSeek 自动前缀；Claude 侧按 PLAN 可配 1h）→ 缓存已死 → **软闸**重建  
2. **tokens 硬顶** → **硬闸**，轮末重建，认赔一次全价  
3. （可选）用户手动「新开一段」

重铸时做的事：写记忆、清空本段 messages 前缀中的对话部分、下轮用新段开场。  
**不是**把旧对话改写成另一种措辞再塞回同一前缀。

验法：响应 usage 的 cache 读字段（DeepSeek/Claude 各记各的）连续为 0 → 查隐形失效源（前缀里混入了每轮变化的东西）。

## 5. 首次进入网页（引导 = 第一次对话）

### 5.1 产品原则（揉进 PLAN §5.2 + 眠眠 09-07 流程）

- 进门就是**对话框**，不是配置向导；第一印象是「它在跟我说话」
- **别问「你有 persona 吗」**；有文件的人走上传/粘贴，多数人靠问答长出来
- 底部输入框**始终可用**；占位：「可以在这里直接打字告诉我哟～」
- 结构化题用**卡片**；打字与点选等价进模型
- 系统提示（安全/禁区）与 persona 分离；引导期用**引导专用短系统提示**，结束后切正式拼装前缀（两套前缀不共享缓存，可接受）

### 5.2 建议状态机（模型提问 + 前端卡片）

| 步 | 问什么 | UI |
|----|--------|-----|
| 0 | 进门自动调一次 API，伙伴开口 | 无用户字；服务端 bootstrap 触发 |
| 1 | 怎么称呼你 | 输入框为主 |
| 2 | 你是「她/他/祂」 | 卡片三选一；输入框可补 |
| 3 | 你要找的是「她/他/祂」 | 卡片；明确是**伙伴**称谓 |
| 4 | 希望伙伴的性格 | 卡片若干默认项；末项「我有对方的 persona」+ 上传/粘贴（仅 md/txt/json） |
| 4a | 若选性格选项 | 模型继续卡片/追问，**有停损**（必填槽位满或最多 N 轮）→ 生成 persona |
| 4b | 若上传/粘贴 persona | 校验后入库，**跳过 4a** |
| 5 | 导入你们的记忆 | 上传/粘贴；或「和 TA 创造新的记忆」 |
| 6 | 还有要补充的吗 | 短问 |
| 7 | 收尾 | 「persona 和 memory 可在菜单查看/修改。现在去找 TA 吧～」 |

收尾后服务端（或本轮 tool）落盘：

- `data/user_profile.json`（nickname、性别、伙伴称谓…；**无 timezone 字段**）— **nickname 即拼装 user_name，不双存**
- `persona.md`（或约定路径）
- `memories/` + `index.json`（导入则提炼；选「新记忆」可先空）

### 5.3 卡片协议（必须有，否则「弹卡片」落不了）

MVP 约定一种即可（推荐 tool，避免正文标记类 bug）：

- tool 例：`ask_user` — `kind`: `choice` | `upload` | `confirm`；`options[]`；`allow_free_text: true`
- 前端渲染卡片；用户点选或输入 → 下一轮当作用户消息（可带 `client_meta: { card_id, values }`）
- **禁止** `[[CARD:]]` 正文协议

### 5.4 导入纪律（摘 PLAN §6）

- 仅 md/txt/json + 粘贴框；不做 PDF/Word
- 他人对话导入：用户事实可吸收；「关系经历」标注为与前 AI 的过去，不冒充本伙伴在场
- 提炼预览确认可后置；MVP 可先写入再菜单里删

## 6. wake：活人感主路径

```
对话中模型判断需要跟进
  → wake_set(delay / wake_at, note, intent)
  → APScheduler date 到点
  → fire：同一拼装管线 + 触发 7b
  → 生成（或沉默）一条助手消息

用户中途说「外卖到了」
  → 模型自己 wake_cancel 或覆盖 wake_set
```

- **不是**策略脚本骰子决定下次几点（脚本随机 auto-arm 不做产品主路径）
- 安静时段/日上限若做，只做**护栏**（拒/改约），不做决策者
- 手动测试用的 `POST /wakes` 可保留，与模型 tool 同源

## 7. 文件与菜单（MVP）

| 资产 | 路径（建议） | 谁可改 |
|------|----------------|--------|
| 系统提示 | 代码内 / `prompts/system.md` | 仅发版 |
| user_profile | `data/user_profile.json` | 引导 + 设置页 |
| persona | `data/persona.md` | 引导 + 菜单编辑（git 回退后做） |
| memories | `data/memories/**` + index | 模型 tool + 菜单查看/删 |
| wake 状态 | SQLite `wakes` | 模型 tool + 调试 API |

菜单：查看/改 persona、浏览记忆；时区若以后要改走服务端/环境配置（或设置页改配置，**仍不进 profile**）。**不**把系统安全提示暴露成可编辑。

## 10. 本文与旧讨论的差异一览

| 旧说法 | 本文 |
|--------|------|
| 每轮「按节点重铸」对话 | 段内追加；重铸仅软/硬闸关段 |
| 活时间进系统前缀 | 禁止；戳在消息上或放后缀 |
| 脚本算 next_auto_wake | 非主路径；模型 tool 定时刻 |
| 系统∪persona 混写 | 必须拆开 |
| 首屏表单填昵称性别 | 首屏即对话；卡片+输入问出来 |
| 时区写入 profile | **否**；服务端配置 + 每轮后缀时间锚 |
